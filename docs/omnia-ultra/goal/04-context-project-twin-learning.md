# Context, Project Twin and learning

The context compiler must make inclusion decisions inspectable and resist
lost-in-the-middle: immutable source segments, hierarchical summaries, pinned
constraints, salience/recency, goal/task state, sparse+dense+graph retrieval,
deduplication, contradiction detection, token budgets and durable continuation
cursors. Newer memory revisions explicitly supersede older facts.

Every non-trivial project, research question or learning objective gets a
Project Twin with a canonical graph, Markdown narrative and an interactive
HTML/CSS/TypeScript/JavaScript atlas. It includes goal, non-goals, roadmap,
blueprint, plan, milestones, task DAG, dependencies, risks, decisions,
artifacts, tests, citations, source/line references, evidence hashes, owners,
confidence and staleness. Source changes mark affected nodes and downstream
views stale; no incompatible fact is silently merged.

Each project also exposes a versioned Project Overview and stable smart title.
They update only after material goal/root/branch/decision/milestone/evidence
changes, preserve user-pinned text and record candidate diff, evidence
watermark, accepted actor, confidence and rollback history.

For science, mathematics, physics, AI/DS/ML, DSA and competitive programming,
the learning workbench should atomically break concepts into prerequisites,
invariants, patterns, derivations, examples, counterexamples, exercises,
proofs, implementation templates, complexity, historical motivation and
research gaps. Suggestions can deepen, broaden, add tests, generate drills,
compare methods or update the roadmap.
