# Omnia original rebuild goal

**Status:** ACTIVE — no completion claim. **Cycle:** rebuild-0001. **Owner:** root integrator.

Omnia is being rebuilt as a new local-first technical AI workspace. This goal is
separate from historical renderer work and does not inherit any old UI Done state.
It remains active until every mandatory item in `DOD.json` has direct evidence from
source, automated behavior, and suitable native/runtime capture. A green fixture,
preview, or structural validator is never sufficient for a native/live claim.

## Product outcome

Deliver a Windows-first Tauri/Rust/React application with exactly three top modes:
**Chat**, **Browser**, and **IDE**. Chat is the default and represents both
project and projectless sessions in one model. Browser and IDE are Omnia-owned
workspaces with a shared chat sidebar. The renderer under `src/rebuild` is original
source: it may learn from extracted apps and open-source research, but may not
import/copy/replicate historical Omnia UI components, CSS, tokens, layout, fixtures,
or a live external editor/application. Native protocols and domain contracts can
be reused when their permissions and lifecycle are verified.

The complete outcome includes durable sessions and tabs, project/file pointer
storage, RAG and retrieval receipts, model/effort routing, goals/plans/DoD,
subagents, skills/tools/MCP/plugins/memory, real web research, native browser and
computer harnesses, local IDE workflows, advanced hot-reload settings,
observability, accessibility, performance, portability, CI and honest README
screenshots. User consent is required for self-improvement migrations and every
external or privileged action.

## Non-negotiable workflow

Every cycle follows `WORKFLOW.md` and the `omnia-evidence-loop` skill:

1. Read this goal, AGENTS, skill, spec, DoD, source register, checkpoint and diff;
   record input hashes so context compaction cannot silently change scope.
2. Audit requirement → source → runtime → evidence and select atomic criteria with
   owner, dependencies, thresholds and test plan.
3. Deep research a genuinely new open-source revision/path each cycle. Rotate
   queries across IDE, browser, agent, harness, tools, MCP, skills, workflow,
   architecture, RAG, memory, UI and especially `everything`, `super`, `power`,
   `pro`, `max`. Record exact files, license, strengths, weaknesses, novelty and
   apply/reject/defer decision. Repeated repo/revision/path is not new research.
4. Read representative extraction source in every upstream category except Zalo,
   detect stale/missing source and check the installed ChatGPT Microsoft Store
   package read-only. Inventory counts never imply parity.
5. Run up to three useful brainstorm/plan improvement passes. Each pass must make
   a concrete decision; stop when it adds no decision. Produce a runnable reference
   workbench and synthesis before integrating product UI.
6. Delegate independent file-owned slices and require independent review. Do not
   let overlapping agents edit the same files. Empty delegation messages resolve
   through `ASSIGNMENTS.md`.
7. Implement complete modules with real handlers and explicit unavailable states.
8. Verify positive, negative, cancel, race, persistence/reload, accessibility,
   performance and native/live behavior where applicable. Capture the real app.
9. Update and re-read spec, DoD, source register and checkpoint. Run evidence,
   stale-hash, architecture, novelty and claim gates. Record blockers and next
   action; blockers are not Done.
10. Publish only a reviewed milestone with commit/tag/README receipt, then return
    to the next incomplete criterion. Never delete or weaken requirements to
    improve percentages.

## Brainstorm decisions (bounded)

### Pass 1 — scope and continuity
A single session identity must survive Chat → Browser → IDE. Project membership is
metadata on a session, not a competing top-level mode. Decision: shared session
controller plus workspace-specific tabs and chat sidebar.

### Pass 2 — evidence and safety
The requested unlimited retry is constrained by idempotency, permission denial and
outcome-unknown states. Decision: default 5 seconds × multiplier 1 with unlimited
attempts only for retryable, unaccepted work; cancellation and unknown acceptance
terminalize or ask the user. All outputs retain provenance.

### Pass 3 — synthesis and resource use
Reference apps provide useful contracts but copying their UI would preserve their
gaps. Decision: build a fresh graphite/light token system, lazy browser/computer
activation, bounded DOM paging/context compaction, and a runnable evidence
workbench that documents why each product decision was made.

## Completion rule

`DOD.json` is the authority for atomic acceptance. A criterion is Done only with
its required evidence paths and a reviewer distinct from its implementer. Partial,
blocked, planned and stale evidence remain visible. Goal completion requires strict
Done for all mandatory criteria, current README/screenshots, verified commit/push/
tag, and a final reread of all canonical documents. Until then report counts as
`done/partial/blocked/planned` and continue.
