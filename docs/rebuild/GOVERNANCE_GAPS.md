# Governance coverage audit and atomic expansion

Date: 2026-11-08. Reviewer/author of this note: `/root/rebuild_governance`.

The first 170 criteria are a sound foundation but still combine several user
actions and omit advanced requests. A broad “transcript actions work” row cannot
prove every action independently. The ledger is expanded with stable additional
IDs rather than deleting or weakening its original rows.

## Required coverage retained

- Rich output/selection actions, safe streamed rendering, sandboxed code canvas,
  binary/encrypted previews, image/video generation and capability-driven adapters.
- Dynamic titles after compact, user title precedence, native export and session
  operations with explicit lineage and persistence.
- Per-prompt capability/memory lookup, editable memory and skill creation,
  cross-session retrieval, parent/child cache/context and feedback-derived updates.
- Academic/domain workflows and evidence/freshness/evaluation catalogs.
- OS settings/computer actions, UIA/vision fallback, recording, browser devtools,
  Google/Bing search and budgeted deep-crawl frontier, workspaces/groups/downloads.
- Advanced generation/provider/system-instruction/role settings, prompt-controlled
  proposals, inheritance/effective state, local models and credential storage.
- Nested goal/plan/report loops, ask-user, real multi-model synthesis, scheduling,
  consented isolated self-improvement/migration/rollback, prompt enhancement.
- Native app screenshots with measured dimensions and current artifact hashes,
  full behavior inventory, resource budgets and honest supported-format catalogs.

## Fresh research applied

`github/spec-kit` distinguishes reviewer-owned requirements-quality checklists
from implementation completion. `everything-claude-code` separates local checks
from target acceptance. The rebuilt spec must preserve both distinctions. Their
exact revisions/paths/hashes are in `GOVERNANCE_RECEIPT.md`.

## Ownership finding

Canonical documents changed concurrently during this workstream. Root must
capture new document hashes after integration. An earlier read hash is stale;
later source/ledger modifications must not inherit an earlier reviewer sign-off.
The gate should validate every required evidence kind, not only nonempty paths.

All new criteria remain planned. This audit is a coverage expansion, not proof
that any app feature is implemented.
