## Novel synthesis and Omnia decisions

1. **Accessibility is a regression contract.** Omnia’s UI acceptance should produce a scoped report with the tested surface, readiness state, violation fingerprint, and baseline comparison. A green structural check alone cannot satisfy this; a new violation must be visible and block the affected criterion.
2. **Stable workspace identity outranks shell presentation.** Chat, Browser, and IDE tabs should retain stable session/workspace IDs and saved geometry while switching surfaces. Transition tests should prove that inactive native hosts are not destroyed and that layout restoration does not overwrite user state.
3. **Capabilities are data, not guessed buttons.** OS-specific controls should render only when a typed capability is available; unavailable capabilities need an explicit state and a negative test.
4. **Token and interaction sources are auditable.** Keep Omnia’s graphite/light tokens in its own semantic source and generate any derived CSS in a deterministic step. Tabs and panels need a named relationship, roving focus, disabled-state behavior, and reduced-motion handling.
5. **Edits need a transaction boundary.** The IDE should preview bounded replacements, include file revision evidence, revalidate before writing, reject traversal/symlink escapes, and surface rollback failures. This is a safety contract, not a visual feature.
