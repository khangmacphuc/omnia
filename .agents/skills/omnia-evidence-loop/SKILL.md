# Omnia evidence loop

Use the repository root containing `docs/rebuild/GOAL.md`. Follow the newest
human instruction when it changes a requirement; record that change in the
spec and DoD instead of silently losing earlier requirements.

1. Read AGENTS, goal, workflow, spec, DoD, source register and checkpoint before
   selecting work. Record their hashes in the cycle manifest. On compact/resume,
   read them again; chat summaries alone do not establish current state.
2. Select atomic criteria and identify real gaps. Research NEW open source and
   exact source files, including everything/super/power/pro/max discoveries.
   Deduplicate repository/revision/path. Record license, novelty, strengths,
   weaknesses and a concrete apply/reject/defer decision. A failed search stays
   a failed search, never a fabricated finding. Inspect extracted references
   without profiles, credentials or unrelated private material.
3. Improve the plan in up to three useful passes by default. Stop a pass when
   it adds no decision. Synthesize references into an original workbench before
   designing the product. Define observable thresholds, ownership and tests.
4. Delegate independent slices with assignment files. Require each implementer
   to self-review and a separate reviewer to inspect actual source and evidence.
   Preserve ownership; do not multiply agents onto the same mutable files.
5. Implement complete modules. The new UI cannot import or copy legacy UI.
   Native protocols remain reusable. Do not embed external live app/editor UIs.
6. Run relevant positive/negative, cancellation, race and reload checks. Diagnose
   root causes before retrying. Retry transient operations only when side effects
   are known; never turn unknown dispatch or denied permission into blind replay.
7. Capture the real UI and test accessibility/performance for affected flows.
   Label browser preview, fixture, packaged desktop and live provider separately.
8. Update spec, DoD, source register and checkpoint. Re-read all changed specs;
   complete the spec checklist and validate hashes/evidence/stage transitions.
   Record blockers with attempts and resolution path; they are not Done.
9. Commit/push/tag verified milestones as already authorized. Report xx/yy with
   direct receipts, unresolved work and next concrete fix/add/optimize/remove.
   Continue the next criterion until the user's actual goal is satisfied.

The gate enforces artifact consistency, not an LLM's private reasoning or the
truth of every human assertion. Keep its limits explicit. Do not report success
from a green validator without reading commands, outputs and runtime evidence.

See `docs/rebuild/WORKFLOW.md` for stages and `ASSIGNMENTS.md` for file ownership.
